# Per-directory file budgets, asserted by scripts/ci/check-package-size.sh.
#
# ONE ENTRY PER LINE:
#
#     <repo-relative dir>   <budget>|exempt   [<waiver>]
#
# Every entry MUST carry a `#` comment block on the line(s) DIRECTLY above it
# saying why the number is that number — the same convention the byte budgets
# in check-bundle-size.sh follow, and the script rejects an entry without one.
# A blank line between the comment and the entry breaks the pairing.
#
# WHAT IS COUNTED lives in the script's header, not here. Short version:
# non-test .go files in a Go package; every tracked file except *.test.ts in a
# frontend directory; per-directory, never recursive.
#
# A DIRECTORY NOT LISTED gets DEFAULT_MAX_FILES (12). That is the standing
# decision — "no grouping passes 12 files without a written reason" — not an
# escape hatch. Registration is earned by size, which is why this file is short
# and every line in it is load-bearing. Deleting an entry does not dodge the
# gate: an over-budget directory falls back to 12 and fails harder.
#
# BUDGETS ARE ZERO-HEADROOM ON PURPOSE, and this is the one place this file
# deliberately diverges from check-bundle-size.sh. Byte budgets need slack
# because bytes move on every edit. A FILE COUNT only moves when someone
# deliberately creates a file — which is exactly the moment worth a thought. So
# a budget is the count on the day it was registered, and the next file trips
# the gate. That trip is cheap to answer and it is the entire mechanism.
#
# THE THIRD COLUMN IS A WAIVER: a temporary allowance ABOVE the budget for a
# directory that is over target today with a split owed. The budget column
# carries the TARGET, so this file records intent rather than ratifying sprawl.
# The script warns for every waived directory, fails if the count exceeds the
# waiver (debt may shrink or hold, never grow), and fails when the count reaches
# the budget so the waiver is DELETED rather than left to rot.
#
# Bumping a budget: change the number, rewrite the comment above it, and append
# a row to scripts/ci/package-size-budget-history.md.


# ── Go packages ────────────────────────────────────────────────────────

# pkg/app — the application shell: the Wails/HTTP-facing method surface,
# settings, the file watcher, parse orchestration, self-update, coaching entry
# points. 54 files, and the in-repo cautionary tale for how a god-package forms:
# every one of those files was individually defensible the day it landed.
#
# PROVISIONAL. This number is today's count, deliberately, because the split
# that pays it is designed but not yet measured — setting an aspirational target
# now would be guessing. The decomposition carves pure logic into leaf packages
# the shell delegates to (pkg/match, pkg/correlate, pkg/aggregate, pkg/bundle,
# pkg/gamedata and pkg/profiles all came out of here the same way), and the
# closing commit of that campaign replaces this line with the measured result
# plus a history row. Until then this entry stops it growing FURTHER, which is
# the part that matters today.
#
# Do NOT reach a lower number by carving out eight two-file packages. That
# trades one bad shape for a worse one, and the CLAUDE.md rule says so.
pkg/app                                       54

# pkg/db — the SQLite store: schema + additive-column registry, the migration
# engine, per-screenshot-type CRUD, the Store interface and its *SQLStore
# implementation. THE CANONICAL CORRECTLY-LARGE PACKAGE: 30 files is one
# responsibility ("own the database") spelled file-per-concern behind one small
# exported API, and it must not be split to chase a number. Embedded assets are
# not counted, which keeps migrations/ — an append-only ledger that grows
# forever by design — out of the arithmetic.
pkg/db                                        30

# pkg/parser — the OCR pipeline: Tesseract invocation, per-screenshot-type field
# extraction, the embedded owdata YAML set, golden-file projection. One
# responsibility with dense per-type files; splitting would put the classifier
# and the extractors it dispatches to on opposite sides of a package boundary
# for no gain.
pkg/parser                                    22

# pkg/cmd — the transport surface: HTTP handlers and middleware in server mode,
# systray/window/self-update wiring in desktop mode, split per endpoint group.
# Ten of the nineteen are !serveronly, so half this package is one build tag's
# worth of desktop chrome — a legitimate reason for the count, not a reason to
# inflate the budget further.
pkg/cmd                                       19
