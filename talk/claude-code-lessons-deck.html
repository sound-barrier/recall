03
Rule

The tiering isn't vibes — it's a frequency-of-need budget

Behavior that should shape every reply lives in CLAUDE.md. Behavior for one subsystem lives in a glob-triggered rule. Facts you look up instead of obey — full command catalogs, env-var tables — live in dev-reference, on demand only.

The doc even protects itself from going stale by refusing to duplicate anything that already has a canonical source.

docs/dev-reference.md

"specific numeric gates (GO_COVERAGE_MIN, Vitest thresholds, bundle budgets) and version pins... are intentionally NOT duplicated here — read them from vitest.config.ts, mise.toml, go.mod, and Brewfile so this doc can't go stale."

04
Rule

Write the "why," not just the "what"

A rule without a reason can't be judged on an edge case it didn't anticipate. The best rule in this repo doesn't say "don't touch this" — it says exactly which invariants break if you do.

.claude/rules/database.md

"These three stay naive-local and are never converted: the correlator's corroborated() compares OCR finished_at HH:MM against the filename HH:MM, and RowsConflict/dedup do string equality — all correct only because the axes match. Re-encoding the key would also force a 19-table lockstep rewrite (no ON UPDATE CASCADE)."

05
Rule

Content lives in exactly one place

frontend/CLAUDE.md used to own the API-design and accessibility rules outright. Both sections are now one line each — pointing at the file that extracted them, and explaining exactly when it fires.

frontend/CLAUDE.md

"The REST API design rules... now live in .claude/rules/api-design.md, which auto-loads when you touch frontend/src/api.ts... read it before adding or changing any /api/v1/... call."

frontend/CLAUDE.md

"Accessibility rules... now live in .claude/rules/a11y.md, which auto-loads when you touch components, styles, App.vue, or test specs."

"Auto-loaded" and "version-controlled" are different axes

The layer that auto-loads topic detail for every matching session is invisible to git log, invisible to a fresh clone, and never lands in a PR. Line 40 of .gitignore sees to that. Deliberate local/shared split, or a gap — worth deciding on purpose, not by default.

memory · reference_claude_dir_gitignored

".claude/ is in .gitignore... so everything under it — including .claude/rules/*.md — is untracked / local-only... Root CLAUDE.md IS tracked; the rule files it points to are not."

07
Rule

Two tracks of memory, on purpose

Curated conventions — hand-edited, reviewed, incident-driven — and auto-captured memory aren't the same thing, and the repo says so out loud.

Doesn't mean CLAUDE.md stopped moving: the most recent commit is still a manual doc sweep — "docs: document taplo/sqlfluff/Biome in the linter tables". Automation took over the debugging-insight layer, not the structural one.

root CLAUDE.md

"Auto memory is on by default (Claude Code ≥ v2.1.59). New debugging insights get recorded automatically — you don't need to hand-append 'conventions' here anymore. Run /memory to review what's been saved."

Lessons from real incidents

The best rules in this repo don't read like style guides. They read like compressed post-mortems.

09
IncidentRule

One incident, two durable artifacts

One bug. A local transport gotcha in the rule file that touches that code — and the standing reason a whole category of feature now requires a failing e2e first. The incident became two different kinds of memory, at two different altitudes.

.claude/rules/api-design.md

"_fetch in api.ts returns undefined for HTTP 204 / 202. r.json() on a no-body response throws SyntaxError — silently broke every 204 writer... in server mode until the e2e caught it."

root CLAUDE.md

"'Stitching a known pattern across layers' is NOT an exemption — the match-deletion feature shipped with a latent r.json()-on-204 bug because no e2e exercised the POST → reload round-trip."

10
Incident

Name the failure class, not just the instance

The first fix patched one eager fetch. The second and third recurrences got the same treatment because the class had already been named — "leaked async path," not "that one flaky test."

memory · reference_app_test_3000_flake

"two more members of the same leaked-async class were root-fixed... Pattern for any future sighting: make the leaked async path deterministic and inert at the resolution layer — don't chase timing."

11
Incident

Real regression vs. environment flake — and revisiting the call

One is a real regression, pinned in the lockfile until upstream fixes it. The other used to be a coin-flip worth re-running — until a seed got pinned, and the standing triage policy had to change the moment the tooling did.

memory · reference_playwright_161_webkit_crash

"Bumping to 1.61.0... ships a newer Linux WebKit that crashes two WebKit-only e2e specs on CI... reproducibly (failed two consecutive CI runs)... Revisit at 1.62."

memory · reference_schemathesis_flake

"schemathesis now runs with a pinned --seed 20260702... so a red run reproduces locally with identical inputs — treat failures as real, not re-run roulette."

12
Incident

The shell you're driving isn't the shell you think

The tool is called "Bash" on this Mac; the shell underneath is zsh. Same genre, different incident: bumping the pinned Go version left a stale GOROOT in every tool shell until the next session healed it. Environment mismatch isn't a one-off — it's a genre worth watching for on its own.

memory · feedback_destructive_shell

"zsh does NOT word-split unquoted variables by default — so for ts in $KEEP where KEEP='a b c' iterates ONCE... I destroyed 23 of the maintainer's curated testdata PNG fixtures with exactly this bug... a real data-loss event... ~30MB of unreplicated, never-committed work."

13
Incident

Verify, don't trust — including the tool's own claims

Two different kinds of stale ground truth: a linter that hadn't caught up to the real toolchain, and a memory that described a fix that had quietly never landed. Neither is hypothetical caution — both cost a real debugging cycle.

memory · reference_go126_new_value_modernizer

"The gopls/LSP in this environment uses PRE-1.26 semantics, so it flags new(value) as 'NotAType' — those diagnostics are STALE, not real. Verify with go build/go test... not the LSP."

memory · reference_vite_ipv6_wails_proxy

"This recurred... because the 07-19 'fix' was never committed... If the symptom comes back, FIRST check that block is still in the file; don't re-diagnose from scratch, and don't trust a memory that says a fix is applied without looking."

14
Incident

Some actions are the human's to trigger, full stop

The boundary exists because it was crossed once. It ships with a named carve-out too — a reversible prep commit stays allowed, because the line is about irreversibility, not caution for its own sake.

memory · feedback_release_maintainer_trigger

"I merged release-please's Release PR #484 to 'cut v0.19.0'... using --admin to bypass branch protection — which published the GitHub Release + signed container before the user had done their intended pre-release steps. A published release can't be cleanly unpublished."

root CLAUDE.md

"'Cut / ship / release vX.Y.Z' authorizes preparation only. Claude must not — without an instruction naming that exact action in the moment — merge release-please's Release PR..., push a v* tag, ...or gh pr merge --admin a release."

15
Rule

CI legibility is a design choice, not an accident

Three separate decisions, one throughline: a green check should mean what it says. Split the job so lint failures and test failures don't look alike. Let a retry show as "flaky," never silently pass. Make every skip explain itself in a file someone will actually read.

.claude/rules/ci-cd.md

"test-unit (split out 2026-07-10 so a failing test never reports as 'lint')"

.claude/rules/ci-cd.md

"CI retries once because shared runners starve rAF/transition chains under load (five distinct single-test failures across four runs on one PR forced this)."

.claude/rules/ci-cd.md

"every t.Skip in pkg/ must appear in scripts/test-skips-allow.txt with a one-line 'why' comment... not for hiding flakes."

Working agreementAct three — collaboration

Two rules that look contradictory, and aren't

The line between them isn't ask-vs-don't-ask — it's scope-vs-execution. Direction decisions are the user's, always. Once scope is agreed, stalling for permission on the steps inside it reads as friction, not care.

memory · feedback_wait_for_scope_answers

"an AskUserQuestion about phase slicing/scope timed out after 60s and Claude proceeded on its own recommendations. The user: 'why did you continue without an answer? that's not what i want.'"

memory · feedback_autonomous_execution

"'continue, there's no need to ask me going forward' partway through the Wails v2→v3 migration... they value velocity on already-approved work; mid-task checkpoints read as stalling."

17
Working agreement

Batch the fan-out

More parallelism isn't automatically more throughput when the constraint is a session budget, not wall-clock time. The fix wasn't a smaller task — it was matching the execution shape to the actual constraint.

memory · feedback_session_limits_batching

"Large parallel subagent fan-outs (e.g. a 49-finding × 2-verifier workflow) exhausted the user's session limit twice mid-run... prefer inline verification over verifier subagents when each check is a targeted read... run them sequentially or in small batches, persist progress between batches."

18
Working agreement

The letter of a convention isn't the spirit of it

A convention is only as real as the mechanism that enforces it. Renaming files to look compliant isn't the same as being compliant — check what actually gates the behavior you want, not what merely resembles it.

memory · feedback_blackbox_test_package

"the _test.go suffix is automatic; what makes a test black-box is the <pkg>_test package clause forcing it through the public API. Renaming files without changing the package declaration would not satisfy the requirement."

19
Closing

The throughline

  • ·Write the why, so the rule survives an edge case it didn't anticipate.
  • ·Codify an incident immediately — twice, if it teaches two different lessons.
  • ·Name the failure class. Patch the instance later, or not at all.
  • ·Verify against ground truth — including the tool's claims, and your own memory of a past fix.
  • ·Keep irreversible actions human-triggered. Everything else, keep moving.
  • ·Let curated memory and auto-captured memory each do the job the other can't.
